# AGENTS.md

Monorepo (Git Submodules) for MeuEmprego.pro. See `docs/MONOREPO_GUIDE.md` and `README.md` for the full submodule workflow.

## Repo structure and Git workflow

- The repo root is an orchestrator only: `Makefile`, `README.md`, `docs/`, and gitlinks to two independent repos:
  - `meuemprego-frontend/` → `git@github.com:wouerner/meuemprego-frontend.git` (Vue 3 + Vite)
  - `meuemprego-backend/` → `git@github.com:wouerner/meuemprego-backend.git` (Go API)
- Each submodule is a separate git repo on branch `master`. Commit + push changes **inside the submodule first**, then stage the submodule and commit the pointer update in the root repo (see README).
- Each submodule has its own `AGENTS.md`/`README.md` with more detail; prefer those when working inside one.

## Commands (from root Makefile)

- `make setup` — init submodules, `npm install`, `go mod download`, copy `meuemprego-backend/.env.example` → `.env`
- `make dev` — frontend (Vite, port 3000) + backend in parallel; backend uses `air` if installed, else `go run cmd/api/main.go` (air is **not** installed here)
- `make dev-docker` — backend + Postgres via Docker Compose, frontend locally
- `make test` — `npm run test` (frontend) then `go test -v ./...` (backend)
- `make build` — frontend `npm run build` + backend `go build -o bin/api cmd/api/main.go`
- `make update-submodules`, `make status`, `make clean`

## Frontend (meuemprego-frontend)

- Stack: Vue 3 + Vite + Vuetify 3 + Pinia + Vue Router + TypeScript. Use **npm** (no pnpm/yarn). No lint script exists.
- `npm run build` = type-check (`vue-tsc --build`) + `vite build`. `@` alias → `src/`. Dev server port is 3000.
- `tsconfig.app.json` excludes `src/**/__tests__/*`, so type-check does **not** cover spec files.
- Tests live in `src/__tests__/*.spec.ts` and exercise Pinia stores + helpers in `src/types/index.ts`.
  - **Currently failing**: `npm run test` errors with `localStorage is not defined`. Vitest runs in the default `node` environment — `vite.config.mts` has no `test` block despite `happy-dom` being a devDependency. Store code needs a DOM env; fix is adding `test: { environment: 'happy-dom' }`.
- Only auth talks to the real backend (`POST /auth/login`, `POST /auth/register`, `GET /users/me` via `src/services/api.ts`, baseURL `VITE_API_URL` default `http://localhost:8080/api/v1`). Candidate/hunter/metrics data is hardcoded mock data inside Pinia stores — don't expect those to hit the API.
- Auth token lives in `localStorage` (`auth_token`/`auth_user`); the axios interceptor redirects to `/login` on 401.

## Backend (meuemprego-backend)

- Go 1.22, chi v5 router, GORM + PostgreSQL, JWT + bcrypt. Module: `github.com/wouerner/runter-backend`. Layered: `cmd/api` (entry) → `handler` → `service` → `repository` → `domain`.
- `go build ./...` passes. **`go test ./...` and `go vet ./...` currently fail**: `internal/service/auth_service_test.go:10` has an unused `internal/repository` import (pre-existing; tests otherwise pass, run them after removing the import).
- `.env` ships with `DB_HOST=postgres` (Docker-oriented). Running `go run` locally against a bare Postgres needs `DB_HOST=localhost` or use `make dev-docker`.
- GORM AutoMigrate runs on startup — no migration tool.
- Swagger UI at `/swagger/index.html`; `docs/` is generated by swaggo/swag (**DO NOT EDIT**) and needs `swag init` to regenerate (not installed).
- Naming gotcha: the backend is branded "Runter" (`runter_backend` module, `runter_db`, `runter_postgres`/`runter_api` containers) while the frontend/root is "MeuEmprego". Both names coexist intentionally.

## Ignored files

- `.env`, `dist/`, `tmp/`, `bin/`, `*.tsbuildinfo` are gitignored; only `.env.example` is tracked. `.env` files exist locally in both submodules and are not committed.
