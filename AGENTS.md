# AGENTS.md

Monorepo (Git Submodules) for MeuEmprego.pro. See `docs/MONOREPO_GUIDE.md` and `README.md` for the full submodule workflow.

## Repo structure and Git workflow

- The repo root is an orchestrator only: `Makefile`, `README.md`, `docs/`, and gitlinks to two independent repos:
  - `meuemprego-frontend/` → `git@github.com:wouerner/meuemprego-frontend.git` (Vue 3 + Vite)
  - `meuemprego-backend/` → `git@github.com:wouerner/meuemprego-backend.git` (Go API)
- Each submodule is a separate git repo on branch `master`. Commit + push changes **inside the submodule first**, then stage the submodule and commit the pointer update in the root repo (see README).
- Each submodule has its own `AGENTS.md`/`README.md` with more detail; prefer those when working inside one.

## Commands (from root Makefile)

- `make setup` — init submodules, `npm install`, `go mod download`, copy `meuemprego-backend/.env.example` → `.env`
- `make dev` — starts Postgres via Docker Compose (`docker compose up -d postgres`), waits for its healthcheck, then frontend (Vite, port 3000) + backend in parallel; backend uses `air` if installed, else `go run cmd/api/main.go` (air is **not** installed here). Ctrl+C kills both (trap `kill 0` INT TERM — use `INT`/`TERM`, not `SIGINT`, since the Makefile runs under `/bin/sh` dash)
- `make dev-docker` — backend + Postgres via Docker Compose, frontend locally
- `make test` — `npm run test` (frontend) then `go test -v ./...` (backend)
- `make build` — frontend `npm run build` + backend `go build -o bin/api cmd/api/main.go`
- `make update-submodules`, `make status`, `make clean`

## Frontend (meuemprego-frontend)

- Stack: Vue 3 + Vite + Vuetify 3 + Pinia + Vue Router + TypeScript. Use **npm** (no pnpm/yarn). No lint script exists.
- `npm run build` = type-check (`vue-tsc --build`) + `vite build`. `@` alias → `src/`. Dev server port is 3000.
- `tsconfig.app.json` excludes `src/**/__tests__/*`, so type-check does **not** cover spec files.
- Tests live in `src/__tests__/*.spec.ts` and exercise Pinia stores + helpers in `src/types/index.ts`. All 11 tests pass (`npm run test`). Note: spec mocks return fresh copies per call — do not share mutable array references across `mockResolvedValue` (tests mutate store state; use `structuredClone`/`mockImplementation`). Throw-based validation tests need `await expect(async () => ...).rejects...` since store functions can throw synchronously.
- Frontend talks to the backend via `src/services/api.ts` (auth, axios baseURL `VITE_API_URL` default `http://localhost:8080/api/v1`) and `src/services/meuemprego-api.ts` (candidates/hunters/access-requests/metrics clients + snake_case→camelCase mappers). Auth token lives in `localStorage` (`auth_token`/`auth_user`); the axios interceptor redirects to `/login` on 401.

## Backend (meuemprego-backend)

- Go 1.22, chi v5 router, GORM + PostgreSQL, JWT + bcrypt. Module: `github.com/wouerner/runter-backend`. Layered: `cmd/api` (entry) → `handler` → `service` → `repository` → `domain`. `go build`, `go vet` and `go test` all pass (28 tests).
- Candidates, hunters, access-requests and metrics modules are wired in `main.go`: `GET /candidates`, `GET/PUT /candidates/me`, `PATCH /candidates/{id}` (`{"approved": true}`), `GET /hunters`, `GET/PUT /hunters/me`, `PATCH /hunters/{id}/status` (`{"status":"Aprovado"}`), `POST /hunters/{id}/contacts`, `GET /access-requests/me`, `POST /access-requests`, `PATCH /access-requests/{id}` (`accepted`/`rejected`), `GET/POST /metrics`. All JWT-protected.
- `internal/database/seed.go` seeds 5 showcase candidates + 5 hunters idempotently after AutoMigrate on startup, plus 3 demo login users (`admin@meuemprego.pro`, `carlos@meuemprego.pro`, `juliana.hunter@meuemprego.pro`, password `password123`) linked to profiles via `user_id`. Role detection is email-based in the frontend (`detectRole` — email must contain `admin`/`hunter`).
- `.env.example` ships with `DB_HOST=localhost` so `go run` works against the compose Postgres (exposed on host port 5432). The `app` service in `docker-compose.yml` hardcodes `DB_HOST: postgres` internally, so `make dev-docker` is unaffected by `.env` changes.
- GORM AutoMigrate runs on startup — no migration tool.
- Swagger UI at `/swagger/index.html`; `docs/` is generated by swaggo/swag (**DO NOT EDIT**) and needs `swag init` to regenerate (not installed).
- Naming gotcha: the backend is branded "Runter" (`runter_backend` module, `runter_db`, `runter_postgres`/`runter_api` containers) while the frontend/root is "MeuEmprego". Both names coexist intentionally.

## Ignored files

- `.env`, `dist/`, `tmp/`, `bin/`, `*.tsbuildinfo` are gitignored; only `.env.example` is tracked. `.env` files exist locally in both submodules and are not committed.
